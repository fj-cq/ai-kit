# 专业材料到易读内容

把专业材料整理成目标读者能理解、判断或使用的内容。按需要选择理解、改写、讲解和网页制作，不要求每次都走完。

**准备：** 原材料、目标读者与用途，以及需要文字还是网页。只需提供你已经知道的信息。

**得到：** 与任务相符的解读、易读稿或 HTML 文件。状态：实验；版本：`0.1.0-draft`。

## 如何开始

让 AI 读取本流程，再附上材料与目标；不能读文件时粘贴本页和实际选中能力的提示词。流程只编排步骤，各能力的 prompt.md 是执行依据。

可从 [示例请求](examples/input.md) 和 [分步参考结果](examples/output.md) 了解一次完整交接。

## 选择路线

| 当前情况 | 执行方式 | 何时结束 |
| --- | --- | --- |
| 只想理解一份报告 | [读懂专业报告](../../prompts/understand-reports/README.md) | 交付解读后结束 |
| 事实和结构已明确，只是文字难读 | [把文字写清楚](../../prompts/write-clearly/README.md) | 交付改写稿；用户需要网页时再继续 |
| 不熟悉其中的概念，需要教学解释 | [把专业内容讲明白](../../prompts/explain-concepts/README.md) | 交付解释；互动时等待读者答题 |
| 已有确定的文字稿，只需排版 | [文字稿转图文网页](../../prompts/text-to-visual-page/README.md) | 交付实际文件和真实检查结果 |
| 需要理解后整理，再形成网页 | 下面的组合路线 | 完成用户要求的最终载体后结束 |

若连任务目标都不清楚，先澄清影响方向的缺口。可阅读 [完善任务要求的外部参考](../../prompts/refine-tasks/README.md)，但它不提供本地提示词，也不是本流程的必经步骤。

## 组合路线与交接

### 1. 理解材料

输入原材料和阅读目的，按“读懂专业报告”形成解读。保留可追溯的事实、原文主张、计算、冲突、限制与新增建议。

**交给下一步：** 原材料仍作为事实依据，解读作为已标识的解释层。缺失附件与未解决冲突一同传递，不能只传一段省略限制的摘要。

### 2. 按目的形成易读稿

用户要求改写时，使用“把文字写清楚”；需要教学时，使用“把专业内容讲明白”。两者都需要时先明确各自段落的用途，教学例子单独标识，不混成原文事实。

若用户要求整理一份新说明稿，可以综合材料与解读，但必须区分已观察结果和新增建议。不能把原文未经证实的主张直接改成事实。单纯忠实改写原报告时，不擅自替换原作者结论；另行指出冲突。

**交给下一步：** 一份确定版本的完整文字稿。核对数字、条件、责任、状态与来源关系。能从材料解决的自行核对；只有影响正确性且无法解决的事实冲突或方向取舍才询问用户，不为每一步增加确认。

### 3. 按需制作网页

只在用户需要网页时，读取“文字稿转图文网页”的完整提示词。它只接收上一环节核对后的文字稿作为排版基线，不再自动改写观点、删减文字或增加案例。

**交付：** 文件及简短检查结论。此处“原文完整保留”指传入排版环节的文字稿；如果前面曾按用户要求重写，不能宣称最终网页逐字保留最初报告。

## 缺口与失败处理

- 缺附件：指出影响范围，继续完成可依据的解读，不能补造缺失图表结论。
- 两份资料冲突：保留各自版本与条件；未能解决的冲突随稿传递，影响决策时请求必要信息。
- 只能对话、不能写文件：先交付文字，说明网页文件未生成；用户需要时提供可保存源码。
- 不能打开浏览器：可完成静态检查，但实际显示、交互或打印应标未验证。
- 任何步骤都不自动发送、发布或替用户批准外部动作。

## 验证、来源与成本

环境依赖由选中的能力决定；文本步骤只需对话，HTML 步骤需要文件输出。AI 产品使用可能产生费用；不强制联网、安装软件或调用外部服务。

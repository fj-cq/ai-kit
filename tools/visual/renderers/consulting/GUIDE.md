# 咨询汇报图形案例

先选要回答的问题，再用结构化输入重画。这里提供 19 个有限规模案例，不是自动理解业务、自动排任意图形的引擎。

## 入口与前置条件

- 从 [Visual Kit](../../README.md) 找到本页；结构图复用现有 [SVG 原语](../svg_diagram.py)，没有另造一套连线底座。
- Python 3.9 或以上，标准库即可；无需网络、账户、外部字体或付费模型。
- 正式位置为 `tools/visual/renderers/consulting/`。临时独立使用时，将环境变量 `VISUAL_LIB` 指向包含 `svg_diagram.py` 的目录。
- 源码、通用案例与测试保存在 tools/visual；输入与产物保存在调用者选择的其他目录。入口拒绝写入 tools/visual，也拒绝覆盖已有文件。

## 选图

| 要回答的问题 | kind / 案例 ID | 本例容量与语义边界 |
|---|---|---|
| 谁高谁低 | `bar` / `quantity-bar` | 最多 8 项，非负、零基线；按输入顺序绘制，排序需在输入中明确 |
| 前后谁改善更多 | `slope` / `quantity-slope` | 两时点、最多 8 项；不是连续时间趋势 |
| 距离目标还有多少 | `bullet` / `quantity-bullet` | 单指标、最多 3 个背景阈值；目标与阈值由输入提供 |
| 怎样随时间变化 | `line` / `quantity-line` | 2–8 个等距时点、最多 3 系列；不推算缺失值 |
| 净变化由什么构成 | `waterfall` / `quantity-waterfall` | 最多 6 项增减；起点加贡献必须等于终点；不自动证明因果 |
| 构成比例怎样不同 | `stacked_bar` / `quantity-stacked` | 最多 8 行、3 类，每行合计 100；不表示各组总规模 |
| 二维位置与第三个规模如何同时比较 | `scatter` / `quantity-scatter` | 最多 7 点；横纵坐标有单位，气泡面积正比规模；不自动判优先级 |
| 缺口集中在哪里 | `heatmap` / `quantity-heatmap` | 最多 6×5；数值变颜色，null 表示未知而非零 |
| 状态处于哪一级 | `harvey` / `quantity-harvey` | 最多 5 项、5 级定义；圆点填充是等级，不是随意推导的完成百分比 |
| 哪些输入缺一不可 | `process` / `process` | 2–8 节点，显式坐标、箭头和共同必要条件；无自动避障 |
| 工作怎样跨角色交接 | `swimlane` / `swimlane` | 2–3 泳道、2–4 步；仅向后推进，不处理复杂回流 |
| 问题如何分解 | `issue_tree` / `issue-tree` | 2–3 分支，每支 1–3 子项；分类完整性和独立性由人判断 |
| 不同职责怎样分层 | `layers` / `layers` | 2–4 层、每层 1–3 项；上下支撑不等于执行先后 |
| 依据与判断怎样逐项对照 | `evidence_table` / `evidence-table` | 2–5 列、1–5 行；密集长文应回到原生 HTML 表格 |
| 谁执行、谁最终负责 | `raci` / `raci` | 最多 5 行；每行恰好一个 A 或 A/R；不是 RAPID 的同义词 |
| 每阶段交付什么 | `roadmap` / `roadmap` | 2–3 阶段，每阶段 1–3 产出；带阶段进入条件或最终验收条件 |
| 哪些任务有时间依赖 | `gantt` / `gantt` | 2–8 等长时段、最多 5 任务；仅“完成后开始”，不是资源调度求解器 |
| 数量从哪里流到哪里 | `sankey` / `quantity-sankey` | 两列，各最多 3 节点；非负、逐行逐列守恒；不支持循环与多阶段 |
| 各组规模和组内构成怎样同时呈现 | `mekko` / `quantity-mekko` | 最多 5 组、4 类；列宽按总量、列内高度按占比；极小单元不强塞标签 |

桑基和 Mekko 属于有条件的进阶案例：先核对数量关系，再判断图是否比表格更容易读。小单元省略内部标签时，完整数据仍保留在 SVG 的可访问说明和图册源 JSON 中。

## 五步使用

以下命令在能力包所在目录运行。输出路径是示例，重复使用时换新文件名。

1. 看可用图形和输入样例。

```bash
python3 render.py --list
```

2. 生成一个现有案例，确认本机依赖正常。

```bash
python3 render.py --case quantity-waterfall --output ../../../../outputs/waterfall.svg
```

3. 从 `diagram-examples.json` 或 `quantitative-examples.json` 取一个对象，另存为业务目录中的输入文件。修改内容后，用自定义入口重画。

```bash
python3 render.py --input ../../../../outputs/input.json --output ../../../../outputs/custom.svg
```

4. 需要全图形选型时，生成离线图册。

```bash
python3 render.py --gallery ../../../../outputs/gallery
```

图册目录含 `index.html`、独立 `svg/`、输入 `specs/` 和带文件摘要的 `manifest.json`；没有远程脚本或字体。可选 `--subset diagrams` 或 `--subset charts`。
输出父目录会自动创建；正常生成退出码为 0，输入错误或拒绝覆盖为 2。

5. 运行检查，再打开真实输出查看中文和关系。

```bash
python3 render.py --self-test
```

`--self-test` 运行能力包内置测试，不会自动验收此前生成的自定义文件；内置测试失败退出码为 1。业务图需另检查实际输出与原输入是否一致。

自动检查通过后仍需在实际使用尺寸目视核对：数字能否读回、单位和来源是否完整、标签是否碰撞、箭头是否穿框、图题是否能被证据支持。小屏图册允许图内横向移动；需要读单图时打开 SVG 放大。

## 共同输入合同

上层选图和职责边界统一见 [Visual Kit](../../README.md)。分类器选择 `renderer: consulting-svg` 时，将其中完整的 `render_spec` 对象单独保存为输入文件；旧 `content_spec.chart_type/nodes/edges` 只是描述，不是本入口格式，必须由调用者按下表及对应示例补齐。程序不推断缺失的来源、单位、坐标或共同必要关系。

每个输入是一个 JSON 对象，必需字段如下。`data` 按选中的案例结构填写，不在案例之外猜测字段。

| 字段 | 含义 |
|---|---|
| `id` | 图形唯一标识；建议小写字母、数字、连字符，如 `warehouse-compare` |
| `kind` | 上表的图形类型，不是案例 ID |
| `title` | 能独立读懂的短图题；不要把假设写成实绩结论 |
| `takeaway` | 这张图支持的一个短判断；程序不会替你验证判断真实性 |
| `question` | 这张图回答的问题 |
| `unit` | 单位或分类口径；涉及多个量时明确各轴与面积单位 |
| `source` | `{ "kind": "synthetic" 或 "provided", "label": "短来源名" }` |
| `boundary` | 图形不支持推出什么结论、数据范围或方法限制 |
| `data` | 精确数据、角色、坐标、时段和关系；不含隐式业务推理 |

`synthetic` 必须显式呈现“合成示例”；`provided` 表示调用者提供了来源名称，图中标注“未核验”，不等于程序认证了真值。完整出处放在业务报告，不把长网址挤进图脚。文字过长、无效数值、错误合计或不满足图形容量时，入口报错，不截断后假装成功。

结构图的 `edges` 需要 `from / to / meaning`；汇合输入需要 `mode: all_required`。不要把并列条件画成串行，也不要把普通关系线称为因果证据。甘特时段从 0 编号，`end` 是不包含在任务中的右端，例如 `start:1,end:3` 占两个时段。

## 嵌回单页或报告

调用者保存原始 JSON 与 SVG，再将同一 SVG 内嵌到 HTML 或编码为 data URI；多图的 `id` 各不相同。底层画布固定 1000×560，保留原蓝色系；使用 tools/visual/render.py 公共入口可选 15 套主题。主题不改变字号和画布，也不增加输出格式转换能力。窄屏用图内滚动／独立大图，单页槽位过小时重新布局或拆图，不靠整体缩小掩盖不可读文字。

返回原入口时分别记录：输入、实际生成文件、退出码、已跑检查与未验证项。原入口负责数据和关系真值、图题是否成立、实际成品中的大小与遮挡以及最终载体验收。这里不接管单页写作、架构建模或发布。

## 常见问题与验证边界

| 现象 | 处理 |
|---|---|
| 找不到 `svg_diagram.py` | 保持 tools/visual/renderers 的目录结构；临时包显式设置 `VISUAL_LIB`，不要复制修改现有原语 |
| 输出文件或图册目录已存在 | 使用新路径，保留旧结果；脚本不提供强制覆盖开关 |
| 标签、来源或单位超长 | 缩短图内文字并保留完整正文，或拆成两图；不要自动省略关键限定词 |
| 合计、比例或依赖检查失败 | 修正输入口径，不能为了能出图改造数据 |
| 程序通过但图上碰撞 | 这是尚未覆盖的具体字体/内容组合；保留输入，补几何或视觉回归，再修排版 |
| 瀑布图需要“基准／结果”而不是“期初／期末” | 当前起终点标签固定；仅当语义一致时加可见说明，否则走定制代码，不把期间含义强加给原数据 |
| 需要原生可编辑 PowerPoint | 另走 PptxGenJS 等原生对象路线；SVG 源码可编辑，不代表 Office 图表数据和流程对象可编辑 |

## 现有 Skill 接入回归

目标：验证调用者能从 页面制作能力 或 报告解读能力 汇报模式找到本入口，按真实输入绘图，再把同一图嵌入 HTML。只用两道固定合成题；这个验证器不能直接验收任意业务报告。

1. 从 `页面制作能力` 冷启动，给定成本基准100万元、运输+18、分拣−7、损耗+9、结果120，输出一页HTML。
2. 从 `报告解读能力` 汇报模式冷启动，给定“需求预测”和“库存信息”共同必要，再依次“计算建议→人工确认→执行”，输出简短HTML报告，不加收益。
3. 两题均给定大纲“一句结论→图→来源与边界”，只授权本地HTML；保留 `a.json/a.svg/a.html`、`b.json/b.svg/b.html` 和选图理由、引用路径、真实退出码。执行者不要先看下面验证器的答案或别人的结果。
4. 主验收者运行相同断言：

```bash
python3 ../../tests/verify_entry_artifacts.py --artifacts ../../../../outputs/consumer
```

5. 用独立手写输入建立可重复对照，并验证损坏案例确实被拒绝：

```bash
python3 ../../tests/verify_entry_artifacts.py --fixture ../../../../outputs/fresh-fixture
```

`--artifacts` 只读；`--fixture` 调用真实绘制入口、保存输出和反例证据，必须指定尚不存在的目录。退出码0表示本固定练习通过，1表示断言失败，2表示调用／路径错误。文件不存在时检查六件产物是否齐备；“同图”失败时核对实际 SVG 是否被重画或替换。本练习只接受直接内嵌 SVG，不覆盖 data URI、任意CSS、安全净化或全部业务表述。

最后仍需在获准的实际载体检查字号、裁切和语义，并让独立读者复述主线。浏览器策略阻断时记录未完成，不切换协议或工具绕过，也不以静态通过宣称成品验收。

本能力不做模型调用、网络请求、业务数据采集、发布、打印 PDF 或 PPT 兼容性验证。固定输入可重复生成固定 SVG；不同机器的字体和最终显示尺寸需复验。

研究口径截至 2026-08-31；首次本机实现与验证为 2026-09-03。这证明了有限输入的本地绘制路径，不是某款 AI 在 2026 年 8 月的一次成图成功率测试。

文字、关系与坐标设计继续引用权威方法，不在这里复制整体表达规则：本工具的输入合同及 SVG 原语文档。

# 快速开始

## 1. 找到能力

先查看 [能力目录](catalog.md)。当前是初始化版本，正式提示词、工具和工作流仍待收录；[能力模板](../templates/capability/README.md) 仅用于贡献时填写。

## 2. 按 AI 的能力选择方式

### 复制文本

当 AI 不能打开链接时，把目标能力说明、提示词和必要的脱敏输入直接粘贴到对话中。不要只贴一个仓库地址就假定 AI 已经读取全部文件。

### 让 AI 读取链接

当 AI 支持网页读取时，先提供 [AI 使用指南](../AI_GUIDE.md) 和目标文件链接，并请它复述所需输入、输出格式及限制。GitHub 页面打开失败时，可以尝试该文件页面上的 Raw 原文入口，或直接粘贴内容。

### 在可执行环境使用工具

若以后目标能力包含脚本，先阅读该能力 README，确认运行环境、安装方式、输入输出及副作用，再在自己授权的本地或 AI 执行环境运行。当前仓库没有统一安装命令，也没有可直接运行的正式工具。

需要本地查看仓库时，可使用：

```sh
git clone https://github.com/fj-cq/ai-kit.git
cd ai-kit
```

复用与分发时，请遵守 [MIT 许可证](../LICENSE) 的版权与许可声明保留要求，并核对第三方材料的独立授权，详见 [许可说明](../LICENSING.md)。

## 3. 核对结果

不要仅凭 AI 说“完成了”判断成功。文本结果需核对事实与输入；可视化需核对数字、单位、图例和数据来源；脚本需按能力说明检查真实产物。若需复现，记录能力路径、Git 提交 SHA、模型或运行环境及脱敏输入。

## 4. 提供反馈

在 [Issues](https://github.com/fj-cq/ai-kit/issues) 选择“使用反馈”或“能力建议”。请提供能够复现问题的最小脱敏输入、期望结果和实际结果。不上传私人文件、公司材料、账号信息或密钥。

如果愿意完善内容，可按 [贡献指南](../CONTRIBUTING.md) 提交 Pull Request。
